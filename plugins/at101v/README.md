# AT101V

Monophonic synthesizer modeled on the Roland SH-101 (1982), with arpeggiator and 100-step
sequencer, plus the extensions listed in the root README. VST3, AU (macOS), LV2 (Linux) and standalone; macOS, Windows and Linux.

| | |
|---|---|
| Version | `AT101V_VERSION` in `CMakeLists.txt` (1.0.0) |
| Plugin codes | manufacturer `Atls`, plugin `At1v` (instrument) |
| Hardware reference | [`docs/hardware-spec.md`](docs/hardware-spec.md), photos in [`docs/ref/`](docs/ref/CREDITS.md) |
| Offline render | `build/plugins/at101v/at101vrender_artefacts/Release/at101vrender preset.json out.wav` |

## Layout

```
Source/dsp/Panel101.h      the panel controls (ids, ranges, defaults): one table for engine, host, UI, presets
Source/dsp/Engine101.h     voice, keyboard logic, clock, arpeggiator, sequencer, poly/unison, FX chain
Source/dsp/Ir3109.h        4-pole OTA filter, closed-form feedback, diode-limited resonance
Source/dsp/Vco101.h        saw / pulse / sub (flip-flop counter) / noise, PolyBLEP
Source/dsp/Modules101.h    ADSR (RC, 1.5x attack target), LFO/clock, chorus, calibration curves (cal101)
Source/dsp/ArpSeq.h        Sequence (100 steps: note, rest, tie, accent, slide, probability) and Arp order
Source/ExtParams101.h      Settings page parameters (preset-scoped unless `global`)
Source/Preset101.h         preset JSON (steps as text: "C2 acc", "-", "G2 slide 50%")
Source/ui/                 PanelView101 (instrument), SeqView101 (step editor), ExtView101 (settings), Bars101
tools/panel101.py          layout (mm) → assets/layout101.json + silkscreen101.png
tools/blender/scene101.py  Blender scene: backgrounds (3 colours), keys down, sprites, hero stills, video frames
tools/pack_assets101.py    renders → assets/ui (JPEG backgrounds, filmstrips, ui.json with layout and key hulls)
tools/presets101.py        factory presets → assets/presets/*.json
tools/level_presets.py     renders each preset and sets VOLUME so all sit at about −17 dBFS RMS
tools/dsptest.cpp          filter response, self-oscillation, arp/seq order, fuzz
```

## Pipelines

```bash
python3 tools/panel101.py                                   # layout + silkscreen
# on pc50-wsl (Blender 5.2, CUDA): copy scene101.py, layout101.json, silkscreen101.png to ~/ai/at101v
blender -b -P scene101.py -- --mode bg,sprites --samples 256 --out out          # ~40 min on the 3090
blender -b -P scene101.py -- --mode hero --samples 200 --preset 16_acid_line.json --out out_hero
blender -b -P scene101.py -- --mode anim --samples 40 --frames 192 --preset 16_acid_line.json --out out_hero
rsync pc50-wsl:ai/at101v/out/ assets/render/out/ && python3 tools/pack_assets101.py
python3 tools/presets101.py && python3 tools/level_presets.py <path to at101vrender>
clang++ -std=c++20 -O2 -ISource/dsp -I../../shared/dsp tools/dsptest.cpp -o /tmp/dsptest101 && /tmp/dsptest101
```

`assets/render/` (raw Blender output) is not versioned; `assets/ui/` is.

Editor self-test without screen capture: `AT101V_SNAPSHOT=/tmp/x.png AT101V_TAB=0|1|2 AT101V_PRESET=n
AT101V_BODY=0|1|2 AT101V_HOLD=note` on the standalone writes a 2x image of the editor after 3.5 s.

## Measured

| What | Value |
|---|---|
| Filter slope | 24 dB/oct (−12 dB at fc → −28 dB at 2·fc, −49 dB at 4·fc) |
| Bass loss with resonance | −9.4 dB at k = 2, −13 dB at k = 3.5 (compensated at the output by 1 + 0.5·k) |
| Self-oscillation | starts just above k = 4; RES 10, KYBD 10: 218 / 436 / 874 Hz for C3 / C4 / C5 |
| Levels | saw at 10, filter open, VOLUME 7.5: −8.8 dBFS peak; presets leveled to ≈ −17 dBFS RMS |
| CPU (offline, M-series, 4x) | ≈ 1 % of a core mono, 3 % with 4-voice unison, 6 % for a 6-voice pad |
| Validation | pluginval strictness 8 (VST3 + AU on macOS, VST3 with GUI on Windows), auval |

## Trampas

- **Self-oscillation never started in the engine** although the filter test oscillated: with all
  mixer sliders at 0 the filter input was exactly zero and the linearized loop had nothing to grow
  from. A −74 dB noise floor (like the real circuit) is mixed in.
- **The MIDI events of the first arpeggio note were lost**: `render()` used to reset the output event
  list, but `keyDown()` runs before `render()` in the block. The processor now clears the list after
  reading it.
- **The camera saw nothing** in Blender: at 300 units of distance the default `clip_end` (100) cut the
  whole scene. Both cameras set `clip_end = 1000`.
- **Pressed keys were invisible** in the top-down view: rotating a key 2° barely moves it on screen.
  The editor darkens the pressed key with a gradient on top of the "all keys down" render.
- **Panel ghosting** on the Sequencer and Settings pages: the backdrop draws the rendered panel under
  the body colour; below ~0.97 opacity the silkscreen shows through and looks like a bug.
- **Presets regenerated by `presets101.py` lose their leveling**: run `level_presets.py` after it.
