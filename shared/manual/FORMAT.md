# Manual format

Each product has its manual in `plugins/<name>/docs/manual/`:

```
en.md        English
es.md        Spanish (Rioplatense, voseo: "elegí", "apretá", like the website)
shots.json   the screenshots the manual uses, and how to take them
img/         the screenshots (generated by scripts/manual-shots.py from shots.json; never edited by hand)
```

The same files feed the manual inside the plugin (the Manual button in the editor, `shared/manual/ManualView.h`)
and the manual pages of the website (`/<name>/manual/`, `/es/<name>/manual/`, built by `scripts/build-web.py`).
Both renderers understand only the subset below, so nothing else may be used.

## Markdown subset

| Element | Syntax | Notes |
|---|---|---|
| Title | `# Text` | once, first line |
| Section | `## Text` | becomes an entry in the table of contents |
| Subsection | `### Text` | |
| Paragraph | plain lines; a blank line ends it | no hard line breaks inside |
| Bold | `**text**` | for control names the first time they appear in a section, and for warnings |
| Inline code | `` `text` `` | file names, values the user types |
| List | `- item` | one level only |
| Steps | `1. item` | only for real sequences (a recipe, an installation) |
| Image | `![Caption](img/name.jpg)` | alone on its line; `name.jpg` must exist in shots.json |
| Table | `| a | b |` with a `|---|---|` second line | short cells; no pipes inside cells |
| Note | `> text` | one paragraph: tips and warnings |

No HTML, no nested lists, no links to other pages, no emojis, no footnotes.

## shots.json

```json
[
  { "file": "overview.jpg",
    "env": { "AT20V_TAB": "0", "AT20V_PRESET": "3" },
    "wait": 4,
    "crop": [0.0, 0.0, 1.0, 1.0],
    "caption_en": "The front panel with the Horn preset.",
    "caption_es": "El panel frontal con el preset Horn." }
]
```

- `env`: the editor's snapshot variables (see each `PluginEditor.cpp`: `<NAME>_SNAPSHOT` is set by the script,
  everything else comes from here). Only variables the editor already understands.
- `wait`: seconds before the snapshot (the editor's own wait variable, if it has one, wins).
- `crop`: `[x, y, w, h]` as fractions of the full editor image, to show one section large. Full image if omitted.
- The image is saved 1600 px wide at most (JPEG), so crops of small areas stay sharp up to about a quarter of
  the editor.

## Writing

Written for musicians who just installed the plugin, not for developers. Plain verbs, sentence case, the
names exactly as they appear on the interface, ranges and units when they help ("0 to 10 s"). Explain what a
control does to the sound, then how to use it. Every feature described must exist in the code; when in doubt,
leave it out. Order: what it is, first steps (installing, loading it in a DAW, first sound), a tour of the
interface, every section and control, presets, MIDI and sync, recipes (step by step), tips and troubleshooting,
specifications. Product names of the original manufacturers only to identify the instrument that inspired
the recreation, as on the website.
